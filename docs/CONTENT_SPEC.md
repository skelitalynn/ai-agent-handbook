# 内容规范

## 1. 文档粒度

一个核心知识点或一组高度相关的问题对应一篇 Markdown。

每个章节目录中的 `README.md` 只负责章节导读、知识结构、前置关系和子文章索引。具体知识点拆成独立 Markdown，并作为二级条目加入 `SUMMARY.md`。

不要：

- 一道小题一个文件
- 一整个章节只有一个超长文件
- 在同一篇中混入多个无关主题

## 2. 正文结构

```markdown
# 问题或主题

## 1. 面试回答
## 2. 工作原理
## 3. 最小实现
## 4. 相关概念对比
## 5. 工程实践
## 6. 常见误区
## 7. 高频追问
## 8. 最小示例
## 参考资料
```

说明：

- “相关概念对比”仅在有必要时添加。
- “面试回答”使用 2～4 句话直接作答，脱离后文也必须准确、完整，不只给背诵口号。
- 不适合代码实现或代码示例的主题可以省略对应部分。
- 简单术语不强行写满全部章节。

## 3. 写作风格

- 专业、清晰、克制
- 先给结论，再讲原理
- 面向已有 AI Agent 基础、正在系统复习的求职者
- 基础章节用于校准概念，不写编程语言入门、环境安装或逐行教学
- 不写行业套话和宏大背景
- 不刻意幽默，不使用网络梗
- 不堆砌英文术语
- 英文术语首次出现时给出中文解释
- 区分官方定义、行业常见做法和工程建议
- 先解释厂商无关的核心机制，再说明具体厂商或框架的实质差异
- 不在结尾机械添加总结

## 4. 代码要求

- 原理说明优先使用最小实现代码，不默认使用抽象伪代码
- 最小实现应尽量可运行或接近可运行；必须抽象时才使用伪代码
- 可运行示例默认使用 Python
- 只有浏览器、Node.js 或 TypeScript SDK 特有主题使用 TypeScript
- 涉及语言差异时再提供对照说明，不强制维护双语言示例
- 不使用高层框架隐藏当前主题
- 教学代码不得冒充生产代码
- 第三方 SDK 示例标注核验日期
- 可运行示例放入 `examples/`，正文只保留关键部分

## 5. 引用要求

优先级：

1. 协议规范和官方文档
2. 原始论文
3. 官方工程博客
4. 官方代码仓库
5. 高质量课程和技术文章

版本或来源发生冲突时，以最新正式稳定版本和最新官方资料为主。预览版、Beta 和实验特性单独标注；已废弃但仍有辨识价值的旧概念仅简短保留，并写明适用版本、废弃状态和最后核验日期。

参考资料必须写明：

- 标题
- 来源
- 链接
- 用于核对的内容
- 最后核验日期

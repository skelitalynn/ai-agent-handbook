# 项目说明

## 1. 项目目标

构建一套系统、准确、可持续更新的 AI Agent 中文知识库，帮助已有 AI Agent 基础的求职者：

- 建立完整的 AI Agent 知识框架
- 理解核心机制，而不是只背术语
- 掌握常见工程实现和失败边界
- 快速复习并准备 AI Agent 相关面试
- 通过最小实现和工程实践理解、验证知识

项目不是零基础教程。“面试回答”是可以独立快速阅读的主要入口；工作原理、最小实现和工程实践用于系统理解与补充。

## 2. 内容依据

项目以 [AI Agent 学习线路](LEARNING_PATH.md) 为主要内容地图。

新增主题必须满足至少一项：

- 属于学习线路现有模块
- 是理解现有模块所必需的前置知识
- 是 Agent 工程中普遍存在的重要问题
- 经审核后明确加入学习线路

不要因为某个框架或产品近期热门，就直接扩展为独立章节。

## 3. 目标读者

- 掌握 Python 或 TypeScript 基础
- 了解 HTTP、API、数据库和 Git
- 能调用模型 API，理解 Prompt、Tool Calling、RAG、Memory 等基本概念
- 做过至少一个简单的 LLM 或 Agent 项目
- 希望系统梳理底层机制、工程边界和知识之间的联系，并准备相关面试

## 4. 内容分层

- **面试层**：简短、准确且可独立成立的面试回答，以及常见误区和延伸追问
- **原理层**：执行流程、状态变化和关键机制
- **实现层**：用于解释机制的最小实现，以及必要的可运行示例
- **工程层**：用于补充和验证理解的设计选择、异常处理、成本、安全和生产限制

读者可以只阅读面试层，也可以继续阅读其余层次进行系统复习。

## 5. 目录与编写顺序

- `SUMMARY.md` 是正式目录和唯一正文编写顺序。
- 从第一章开始，完整写完一章后再进入下一章。
- 每个章节目录中的 `README.md` 只承担章节导读、知识结构、前置关系和子文章索引。
- 一个核心知识点或一组高度相关的问题对应一篇独立 Markdown，并作为二级条目加入 `SUMMARY.md`。

## 6. 文件职责

- `docs/LEARNING_PATH.md`：知识地图和资料入口
- `SUMMARY.md`：正式知识库目录和正文编写顺序
- `research/`：来源整理、分歧和版本核验
- `chapters/`：面向读者的正文，包括待人工审核的初稿
- `examples/`：可运行代码
- `sources/`：统一来源索引
- `PROMPT.md`：单篇内容生成指令
- `AGENTS.md`：AI 修改仓库时的规则

## 7. 生产流程

1. 按 `SUMMARY.md` 的顺序确定当前章节，并规划该章的子文章。
2. 检索学习线路中的已有链接和补充资料，写入 `research/`。
3. 按内容规范将正文初稿直接写入 `chapters/`。
4. 新增、删除或移动正文时同步更新 `SUMMARY.md`，并更新 `CHANGELOG.md`。
5. 发布前人工检查定义、来源、版本、代码和版权风险。
6. 将审核后的版本发布到语雀。
7. 如果在语雀修改正文，将修改同步回仓库；仓库 Markdown 保持为唯一内容源。

## 8. 技术与版本立场

- 先用厂商和框架无关的方式解释核心机制，再说明 OpenAI、Anthropic 等具体实现的实质差异。
- LangChain、LangGraph、LlamaIndex 等框架只用于解释其特有抽象，不用高层 API 代替底层原理。
- 示例不强制覆盖所有厂商，必须说明实际采用的实现、适用版本和最后核验日期。
- 结论以最新正式稳定版本和最新官方资料为主。
- 预览版、Beta 和实验特性不替代稳定版，只作为单独提示。
- 已废弃但仍有面试辨识价值的概念可以简短保留，必须明确标注旧版本、废弃状态和适用条件。
- 不把存在冲突的新旧版本揉成同一个结论。

## 9. 发布标准

正文发布前必须满足：

- 核心结论有可靠来源支持
- 快速变化的信息标注核验日期
- 版本结论符合最新正式稳定版本；旧版和实验特性已明确标注
- 没有把单一框架实现写成行业标准
- 最小实现和可运行示例逻辑成立
- 没有大段复制或近似改写第三方内容
- 不包含虚构的企业案例、性能数据或面试频率
- 内容与学习线路或项目范围一致

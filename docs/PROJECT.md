# 项目说明

## 1. 项目目标

构建一套系统、准确、可持续更新的 AI Agent 中文知识库，帮助有 CS 或后端基础、希望转向 AI Agent 并准备求职的读者：

- 建立完整的 AI Agent 知识框架
- 理解核心机制，而不是只背术语
- 掌握常见工程实现和失败边界
- 快速复习并准备 AI Agent 相关面试
- 通过最小实现和工程实践理解、验证知识

项目不是编程零基础教程，但必须完整建立理解 AI Agent 所需的模型、推理和系统前置知识。第 01 章起，正文前部提供可以独立快速阅读和背诵的面试速记，后部提供可以形成完整心智模型的教材正文；第 00 章只承担全书 Overview。原理、实现、实验和工程实践不是补充材料，而是系统学习主线。

## 2. 内容依据

项目使用三份互相分工的核心文档：

- [AI Agent 学习线路](LEARNING_PATH.md) 界定知识范围并汇总资料入口。
- [AI Agent 全局知识地图](KNOWLEDGE_MAP.md) 展示系统骨架、概念分类和跨章节依赖。
- 根目录 `SUMMARY.md` 按能力递增给出唯一正式教材顺序。

新增主题必须满足至少一项：

- 属于学习线路现有模块
- 是理解现有模块所必需的前置知识
- 是 Agent 工程中普遍存在的重要问题
- 经审核后明确加入学习线路

不要因为某个框架或产品近期热门，就直接扩展为独立章节。

## 3. 目标读者

- 掌握 Python 或 TypeScript 基础
- 了解 HTTP、API、数据库和 Git
- 了解操作系统或分布式系统中的基本工程概念
- 可以尚未系统学习 LLM 和 Agent，但能够阅读技术文档与 Python 或 TypeScript 示例
- 希望从已有 CS 或后端能力迁移到 AI Agent，系统理解底层机制、工程边界和知识联系，并准备相关面试

## 4. 内容分层与阅读路线

- **面试层**：第 01 章起，在文章前部提供覆盖知识主干的背诵提纲、可选的高频对比和 3～5 个带回答要点的深入追问
- **教材层**：文章后部完整解释问题来源、机制、推导、边界和工程后果
- **验证层**：最小实现、可运行示例、实验、练习和验收标准

项目提供三条阅读路线：通过第 01 章及后续文章顶部进行面试速查；按 `SUMMARY.md` 顺序进行系统学习；通过正文编号对应的实践目录完成示例、实验和练习。三条路线共享同一套正文，避免维护相互漂移的面试版和教材版。完整规则见 [内容架构设计](CONTENT_ARCHITECTURE.md)。

## 5. 目录与编写顺序

- `SUMMARY.md` 是正式目录和唯一正文编写顺序。
- `SUMMARY.md` 按能力递增组织，不按厂商产品、热门术语或专家分类目录组织。
- 第 00 章先建立完整 Agent 系统骨架，后续章节必须说明自己在骨架中的位置。
- 从第一章开始，完整写完一章后再进入下一章。
- `chapters/` 下的一级子目录对应一篇，目录名格式为 `篇编号-英文主题`，例如 `1-llm-foundations/`。
- 正文文件使用全书连续的两位编号，格式为 `NN｜正文标题.md`；`SUMMARY.md` 直接链接正文文件。
- `README.md` 不默认创建，也不得承载正式正文；只有确有独立导航需要时才作为目录说明使用。
- 正文按完整认知主线和可独立建立的心智模型划分；面试题和简单术语不直接决定文件边界。
- 正文标题优先使用陈述性的知识主题，面试问题作为文章内入口和章节索引存在。
- Evals 和 Tracing 在引入 RAG、Memory、Planning、Workflow 和 Multi-Agent 之前系统讲解，使后续能力扩展可以持续评测和调试。

## 6. 文件职责

- `docs/LEARNING_PATH.md`：知识范围和资料入口，不承担正式编写顺序
- `docs/KNOWLEDGE_MAP.md`：Agent 系统骨架、问题域、组件关系和跨章节依赖
- `docs/CONTENT_ARCHITECTURE.md`：篇、章、文章层级，阅读路线和全书能力递增规则
- `SUMMARY.md`：正式教材目录和唯一正文编写顺序
- `research/`：来源整理、分歧和版本核验
- `chapters/`：面向读者的正文，包括待人工审核的初稿
- `examples/`：可运行代码
- `sources/`：统一来源索引
- `PROMPT.md`：单篇内容生成指令
- `AGENTS.md`：AI 修改仓库时的规则

## 7. 生产流程

1. 从全局知识地图确认当前章节在 Agent 系统中的位置、前置依赖和阶段能力。
2. 按 `SUMMARY.md` 的顺序确定当前正文，先完成文章边界、面试入口和实践路线设计。
3. 人工审核章节骨架；骨架或文章边界不稳定时暂停正文生成。
4. 检索学习线路中的已有链接和补充资料，写入 `research/`。
5. 按内容规范将正文初稿直接写入 `chapters/`。
6. 新增、删除或移动正文时同步更新 `SUMMARY.md`，并更新 `CHANGELOG.md`。
7. 发布前人工检查定义、来源、版本、代码和版权风险。
8. 将审核后的版本发布到语雀。
9. 如果在语雀修改正文，将修改同步回仓库；仓库 Markdown 保持为唯一内容源。

## 8. 技术与版本立场

- 先用厂商和框架无关的方式解释核心机制，再说明 OpenAI、Anthropic 等具体实现的实质差异。
- LangChain、LangGraph、LlamaIndex 等框架只用于解释其特有抽象，不用高层 API 代替底层原理。
- 示例不强制覆盖所有厂商，必须说明实际采用的实现、适用版本和最后核验日期。
- 结论以最新正式稳定版本和最新官方资料为主。
- 预览版、Beta 和实验特性不替代稳定版，只作为单独提示。
- 已废弃但仍有面试辨识价值的概念可以简短保留，必须明确标注旧版本、废弃状态和适用条件。
- 不把存在冲突的新旧版本揉成同一个结论。

## 9. 发布标准

正文发布前必须满足：

- 核心结论有可靠来源支持
- 第 01 章起，面试速记的背诵提纲能够从教材正文推导、覆盖知识主干并包含必要限定
- 高频对比只在概念确实容易混淆且具有相同比较维度时出现
- 高频追问沿主问题继续深入，覆盖原理、边界、取舍、失败或生产落地，而不是罗列相邻概念
- 正文建立完整心智模型，而不是只列出面试结论和术语
- 第 00 章提供系统学习入口；第 01 章起提供面试速查、系统学习和实践验证入口
- 章节明确说明其在全局骨架中的位置、前置能力和学完后的阶段成果
- 快速变化的信息标注核验日期
- 版本结论符合最新正式稳定版本；旧版和实验特性已明确标注
- 没有把单一框架实现写成行业标准
- 最小实现和可运行示例逻辑成立
- 没有大段复制或近似改写第三方内容
- 不包含虚构的企业案例、性能数据或面试频率
- 不包含与正文没有实质对应关系的装饰性引用
- 内容与学习线路或项目范围一致

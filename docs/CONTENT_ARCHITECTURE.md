# 内容架构设计

## 1. 设计目标

本项目同时服务两种阅读需求：

- 求职者可以直接阅读、复述和扩展面试答案。
- 希望系统学习的读者可以沿知识依赖理解原理、实现和工程后果。

两种需求使用同一套正文，不维护彼此容易失去同步的“面试版”和“教材版”。第 01 章起采用“前部面试速记、后部教材”的双层结构；第 00 章负责建立全书 Overview，不设置面试层。项目通过不同索引提供面试速查、系统学习和实践三条阅读路线。

## 2. 信息层级

正文使用三个层级组织：

| 层级 | 划分依据 | 示例 |
|---|---|---|
| 篇目录 | 一个能力递增阶段，包含若干连续编号的正文 | `chapters/1-llm-foundations/` |
| 正文文件 | 一条完整的认知主线或一组共同解释同一过程的问题 | `01｜LLM 的训练与推理.md` |
| 文内小节 | 正文内部的机制、概念或工程问题 | Causal Mask、Prefill、KV Cache |

篇目录只负责分组，不承载正文；正文文件同时是 `SUMMARY.md` 中的正式编号单元。正文不以面试题数量划分，一个概念不默认对应一个文件，一道面试题也不默认对应一篇正文。文件标题优先使用陈述性的知识主题，不为套用问答模板制造“X 和 Y 有什么区别”之类的标题。

判断两个主题是否适合放在同一篇时，依次检查：

1. 它们是否共同解释同一个计算过程、系统边界或工程决策。
2. 是否可以用一条连续叙事从前者自然推导到后者。
3. 是否共享主要前置知识和最小实现。
4. 删除其中一个主题后，文章的核心心智模型是否仍然完整。

如果前三项大多不成立，应拆分；如果只是同一机制下的不同追问，应保留为文章内小节或面试追问。

## 3. 一套正文，三条阅读路线

### 面试速查路线

读者从 `SUMMARY.md` 进入第 01 章及后续正文，只阅读文章开头的“面试速记”，并通过背诵提纲、高频对比和追问定位知识点。第 00 章属于系统学习入口，不纳入面试速查路线。

### 系统学习路线

读者按照 `SUMMARY.md` 的正文顺序阅读完整文章。顺序必须体现知识依赖，而不是热门程度、厂商目录或面试题列表。

### 实践验证路线

读者根据正文编号进入 `examples/` 下的同编号目录、实验、练习和验收标准。实践用于验证正文中的机制与工程结论，不另建一套重复教材。

## 4. 正文的双层结构

### 面试层

第 01 章起，正文开头使用以下结构：

```markdown
# Transformer 与自回归语言模型

> 本文解决什么问题，以及它与本章其他文章的关系。

## 面试速记

### 背诵提纲

**定义**

使用简短、准确、可以直接背诵的完整句子给出定义。

**完整链路或关键机制**

按照当前主题的知识结构，继续列出流程、组件、分类、边界和工程影响。

### 高频对比

只在存在容易混淆、适合按相同维度比较且具有面试或工程判断价值的概念时保留；否则省略整个小节。

### 高频追问

#### 追问：一个沿主问题继续深入的问题

用 1～3 句话给出回答要点。

#### 追问：一个考察边界、失败或工程取舍的问题

用 1～3 句话给出回答要点。

---
```

“背诵提纲”承担八股速记功能，必须覆盖教材正文的完整主干，而不是只给一段抽象总结。它通常先给定义和完整链路，再用加粗的概念名称作为记忆锚点，说明必要的工作原理、分类、边界和工程影响。不同主题使用不同锚点，不机械套用“定义、优点、缺点、场景”等固定字段。

背诵提纲使用短而完整的句子，不以牺牲准确性换取口号化；不放长篇推导、实现代码、论文历史和装饰性引用。它压缩教材结论，但不能引入教材没有解释的新结论，也不能与教材使用不同限定。

“高频对比”是可选结构。只有概念确实容易混淆、能够在相同维度上比较，并且比较结果有助于回答面试题或做工程判断时才使用 Markdown 表格。处于不同系统层级、仅因出现在同一篇正文而被并列的概念，不强行比较。

“高频追问”列出 3～5 个面试官围绕背诵提纲中的核心机制可能继续提出的问题，并为每个问题提供简短回答要点。追问不是同一领域的概念清单，而应沿核心机制形成连续的深入链路，重点考察：

- 候选人是否真正理解工作原理
- 是否知道该机制的适用边界
- 是否理解不同方案之间的取舍
- 是否考虑异常、失败和边界情况
- 是否具备调试、评测和生产落地意识

基础定义和直接分类已经由背诵提纲承担，不再用“什么是另一个概念”填充追问。追问应从提纲中的核心机制继续追究原因、代价、失败条件和验证方法。

### 第 00 章例外

第 00 章是全书的系统 Overview，职责是先建立 Agent 全景、组件位置和学习地图，不是正式八股的起点，因此不设置“面试速记”、背诵提纲、高频对比或高频追问。标题和导语之后直接进入教材正文，也不需要为了表示缺少面试层而保留空标题或分隔线。

### 追问设计示例

以下写法不合格：

```text
什么是 Tool Calling？
什么是 ReAct？
Agent 有哪些类型？
有哪些 Agent 框架？
什么是 Multi-Agent？
```

这些问题只是围绕 Agent 继续罗列概念，与主问题没有形成追问链路。以“Agent Loop 如何运行”为主问题时，更合适的追问是：

#### 追问：如何判断 Agent Loop 应该终止？

通常需要同时考虑模型是否返回最终答案、最大执行步数、时间与成本预算、不可恢复错误以及人工审批状态。不能只依赖模型自行判断任务已经完成。

#### 追问：为什么设置最大步数仍然不能彻底解决死循环？

最大步数只能限制损失，不能解决循环产生的原因。仍需通过 Trace 检查工具结果不足、状态未更新、重复调用检测失效或终止条件不明确等问题。

#### 追问：多个工具调用什么时候可以并行？

工具之间不存在数据依赖、共享状态冲突和高风险副作用时可以并行。是否并行还需要考虑外部服务限流、成本和结果合并方式。

#### 追问：什么情况下不应该使用 Agent Loop？

当执行步骤固定、规则明确且结果要求高度可预测时，应优先使用普通代码或确定性 Workflow。引入 Agent Loop 会增加延迟、成本和不可控性。

#### 追问：如何判断一次 Agent 失败是模型问题还是工具问题？

应结合完整 Trace 检查模型选择的工具、生成的参数、工具执行结果以及后续决策。只看最终答案无法定位失败发生在哪一层。

### 教材层

分隔线之后进入完整正文。正文不再强制套用“工作原理、相关概念对比、工程实践、常见误区”等固定顺序，而应根据主题选择最自然的叙事结构。

教材层可以按照文章自身的论证和执行结构使用少量二级、三级标题及分点，帮助读者识别阶段、组件、条件和结论。段落仍是默认表达方式；只有多个内容确实并列、需要逐项比较或构成步骤时才使用列表。不要为追求形式整齐而把连续论述切成大量单句标题、碎片化段落或只有一项的列表。

完整正文通常需要回答：

- 这个问题为什么产生，它在完整知识图谱中位于哪里。
- 核心对象、状态和执行过程是什么。
- 结论如何从机制推导，而不是只给经验规则。
- 最小实现或实验怎样验证关键机制。
- 机制会带来哪些正确性、延迟、成本、安全和可维护性后果。
- 它与相邻概念的边界是什么，常见误解为什么错误。
- 读者学完后应能解释、实现或判断什么。

不同主题可以采用不同结构。例如，算法主题可以按“问题—推导—实现—复杂度—工程影响”展开；协议主题可以按“角色—消息—生命周期—错误—安全”展开；架构主题可以按“约束—组件—数据流—失败模式—权衡”展开。

### 教材层的辅助表达

在有助于解释工作原理、执行顺序、组件关系或方案差异时，可以补充：

- 纯文本流程图
- 纯文本时序图
- 纯文本架构图
- Markdown 表格

流程图、时序图和架构图必须使用代码块中的纯文本形式，通过箭头、缩进、分支和简单框线表达。例如：

```text
用户请求
   ↓
调用模型
   ↓
是否需要调用工具？
   ├── 否 → 返回最终答案
   └── 是
         ↓
      执行工具
         ↓
      写回工具结果
         ↓
      再次调用模型
```

图表必须承担解释任务，不能只是把相邻段落原样换成另一种格式：

- 流程图用于表示步骤、条件和循环。
- 时序图用于表示多个参与方之间按时间发生的消息与状态变化。
- 架构图用于表示组件、边界、依赖和数据流向。
- Markdown 表格用于比较多个对象在相同维度上的差异。

关系用两三句话即可说清时，优先使用正文；只有一个对象或一个步骤时，不强行画图。正文必须在图表前后解释读者应该观察什么，不能让图表脱离论述独立存在。

## 5. 篇目录与正文文件的职责

`chapters/` 下的一级子目录对应全书的一篇，例如 `1-llm-foundations/`。篇目录只用于容纳同一能力阶段的若干正文文件，不默认创建 `README.md`，也不使用 `README.md` 承载正式正文。

正文文件遵守以下命名和导航规则：

1. 使用全书连续的两位编号，而不是在每个篇目录内重新编号，例如 `00`、`01`、`02`。
2. 文件名格式为 `NN｜正文标题.md`，其中分隔符是全角 `｜`，标题与正文一级标题保持一致。
3. `SUMMARY.md` 直接链接正文文件；目录存在不表示其中正文已经完成或发布。
4. 每篇正文自己说明在全局骨架中的位置、前置关系、核心问题和学完后的能力，不依赖额外的章节导读才能成立。
5. 示例和研究材料不放入 `chapters/`；需要时分别在 `examples/` 与 `research/` 下使用正文编号建立对应目录。
6. 只有某个篇目录确实需要独立的导航说明、且这些信息无法由 `SUMMARY.md` 和正文承担时，才可以增加 `README.md`；它只能作为目录入口，不能替代正式编号正文。

同一问题可以在不同正文中出现，但必须区分用途。例如，Chain-of-Thought 可以在 LLM 基础中解释其能力来源和边界，在 Prompt 章节说明使用方法，在 Evals 章节讨论如何评测；后文应引用前文，不重复复制整段正文。

## 6. 全书能力递增骨架

`SUMMARY.md` 不是领域术语分类表，而是读者从零散 CS 或后端知识走向完整 Agent 工程能力的严格学习顺序。全书采用以下递进结构：

1. 第 00 章先展示完整 Agent 系统，使 Model、Tool、State、Context、Runtime、Environment、Evals 和 Trace 都有明确位置。
2. 第一篇解释模型如何完成一次受控生成，使读者能够理解并实现可靠模型调用。
3. 第二篇从最小 Agent Loop 开始，再深入 Tool、State 和 Context，形成可运行的单 Agent。
4. 第三篇立即建立 Evals 与 Tracing，使后续复杂能力始终可以测量和调试。
5. 第四篇加入 Retrieval、RAG 和 Memory，扩展外部知识与长期信息。
6. 第五篇加入 Planning、Workflow、Human-Agent Interaction 和 Multi-Agent，处理复杂任务与协作。
7. 第六篇在理解底层机制后再学习 Runtime、Harness、Framework、MCP、Skills 和 A2A。
8. 第七篇组合产品架构、多模态、实时交互和环境操作。
9. 第八篇完成 Reliability、Security 和 Production Infrastructure 的生产闭环。

完整组件关系、跨章节概念归属和每篇阶段成果见 [AI Agent 全局知识地图](KNOWLEDGE_MAP.md)。正式章节编号和学习顺序以根目录 `SUMMARY.md` 为准。

### 第 00 章必须是一章真正的教材

第 00 章不只解释如何阅读，而应提供全书反复引用的 Agent 系统骨架、最小执行循环、组件职责、横切约束和知识地图。它只建立最小概念，不提前复制后续章节的完整原理。

### 每一篇必须产生阶段性能力

篇章边界不只按名词领域划分，还要回答“读者学完后新增了什么可以解释、实现或验证的能力”。各篇应提供贯穿式实践，使读者可以在暂时完整的系统上逐层增加能力，而不是长期积累无法组合的孤立知识。

### Evals 与 Tracing 前置

Evals 和 Tracing 位于 RAG、Memory、Planning 和 Multi-Agent 之前。它们不是生产部署前的附加主题，而是后续每次增加模型、Prompt、工具、数据源或控制策略时的反馈机制。

### 正文生成门禁

新章开始写正文前，必须先完成并审核：

- 本章在全局系统骨架中的位置
- 前置章节和读者已有能力
- 本章完成后新增的能力
- 文章划分及每篇完整因果链
- 面试索引和实践验证路线

骨架或文章边界尚未稳定时，暂停正文生成，不能用已经生成的文章反向合理化目录。

## 7. 向全项目泛化

双层文章和三条阅读路线适用于整个项目，但正文结构不能机械统一：

- 原理类主题强调推导、最小实现和复杂度。
- API 与协议类主题强调对象模型、生命周期、版本和错误语义。
- 工程类主题强调约束、数据流、失败模式、可观测性和权衡。
- 安全类主题强调资产、信任边界、威胁、控制措施和剩余风险。
- 框架类主题先解释框架无关机制，再说明具体产品的映射和差异。

全项目统一的是阅读入口、质量标准和知识依赖，不是每篇文章的二级标题。第 01 章起，面试速记负责提供背诵骨架、必要对比和追问链路，教材正文负责完整理解，实践材料负责验证；三者共同构成学习闭环。第 00 章只承担全书 Overview 和系统学习入口。

# 第 10 章研究记录：Retrieval、RAG 与 Agentic Search

> 状态：待人工审核的资料核验记录。最后核验日期：2026-07-22。

## 研究问题

1. Retrieval、RAG 与 Agentic Search 分别位于系统的哪一层，为什么不能互相替代？
2. 数据从源系统进入可查询索引时，切分、权限、版本、更新和删除需要保持哪些不变量？
3. 稀疏检索、稠密检索、混合检索和重排分别解决什么问题？
4. 怎样验证失败发生在检索、证据组织还是生成阶段？
5. 什么时候固定 RAG 足够，什么时候才值得引入可迭代搜索循环？

## 范围边界

- 本章讨论外部知识进入 Agent 上下文的检索链路，不把会话状态和长期用户记忆重新归入 RAG；Memory 留给第 11 章。
- 本章解释索引生命周期、查询和证据链，不展开搜索引擎分布式存储、近似最近邻算法的全部实现细节。
- 厂商功能只用于说明当前落地映射；核心结论保持厂商无关。
- Agentic Search 指由 Agent 根据中间证据继续改写、拆分或补充查询的受预算循环，不等于“用了搜索工具”。

## 一手资料与采用结论

### 1. Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks

- 来源：Lewis 等人的原始论文，NeurIPS 2020。
- 链接：https://arxiv.org/abs/2005.11401
- 采用结论：RAG 将参数化生成模型与可检索的非参数化外部记忆结合；外部索引支持知识更新和证据来源追踪，但检索到文档不自动保证最终回答正确。
- 正文用途：界定 Retrieval 与 RAG 的关系，并说明外部知识库相对参数知识的工程价值。
- 最后核验日期：2026-07-22。

### 2. Dense Passage Retrieval for Open-Domain Question Answering

- 来源：Karpukhin 等人的原始论文，EMNLP 2020。
- 链接：https://arxiv.org/abs/2004.04906
- 采用结论：双编码器把问题和段落分别编码为稠密向量，再用向量相似度检索；它能表达词面不完全相同的语义相关性，但不意味着精确标识符检索天然可靠。
- 正文用途：解释稠密检索的计算边界，并与词项匹配形成互补关系。
- 最后核验日期：2026-07-22。

### 3. BEIR: A Heterogeneous Benchmark for Zero-shot Evaluation of Information Retrieval Models

- 来源：Thakur 等人的原始论文，NeurIPS Datasets and Benchmarks 2021。
- 链接：https://arxiv.org/abs/2104.08663
- 采用结论：跨异构任务的零样本检索表现差异明显；BM25 是稳健基线，复杂重排模型常能提高质量但付出更高计算成本。不能用单一公开数据集替代目标业务评测。
- 正文用途：支持“检索器必须按业务查询和语料评测”以及质量—延迟取舍。
- 最后核验日期：2026-07-22。

### 4. Retrieval

- 来源：OpenAI API 官方文档。
- 链接：https://developers.openai.com/api/docs/guides/retrieval
- 采用结论：当前 Vector Store 文件可自动完成切分、Embedding 和索引；查询支持属性过滤、排序配置、分数阈值与混合检索权重。属性过滤在语义检索前应用，混合检索融合语义与稀疏关键词信号。
- 正文用途：核对托管检索当前能力，并证明权限/属性过滤与检索排序属于不同阶段。
- 版本说明：默认切分参数和具体 API 字段可能变化，正文不把当前默认值写成通用原理。
- 最后核验日期：2026-07-22。

### 5. File search

- 来源：OpenAI API 官方文档。
- 链接：https://developers.openai.com/api/docs/guides/tools-file-search
- 采用结论：当前 File Search 是模型可调用的托管工具；可以限制返回结果数量，响应中的文件引用和原始搜索结果具有不同包含方式。
- 正文用途：说明“模型收到证据”“用户看到引用”和“Trace 保留搜索结果”是三个需要分别设计的输出面。
- 最后核验日期：2026-07-22。

### 6. Contextual Retrieval

- 来源：Anthropic 官方工程博客。
- 链接：https://www.anthropic.com/engineering/contextual-retrieval
- 采用结论：孤立 Chunk 可能失去文档级上下文；可在索引前为 Chunk 增加简短上下文，同时结合 BM25、Embedding、融合和重排。该文的实验数字和特定候选数量只适用于其测试条件，不作为通用默认值。
- 正文用途：解释切分造成的语义损失、混合检索和重排的常见组合。
- 最后核验日期：2026-07-22。

## 术语与架构决策

### Retrieval、RAG 与 Agentic Search

- Retrieval：从候选集合中选择与查询相关且调用者有权访问的证据。
- RAG：把检索证据放入生成输入，并要求生成结果受证据约束；它包含 Retrieval，但还包含证据组织、生成和引用。
- Agentic Search：Agent 根据中间结果决定是否继续检索、如何改写查询以及何时停止；它可以为 RAG 收集证据，也可以只返回搜索结果。

### 权限过滤的位置

权限过滤必须在候选文档进入稀疏和稠密评分之前生效。先做全库 Top-k、再删除无权结果，不仅可能暴露分数、摘要或缓存痕迹，还会因为合法结果被挤出 Top-k 而降低召回率。正文把这一点作为安全不变量，而不是性能优化建议。

### 更新与删除

索引是源数据的派生视图。每条 Chunk 必须能追溯到稳定文档 ID、版本和权限策略；新版本替换应避免新旧 Chunk 混杂，删除必须传播到稀疏索引、向量索引、缓存和引用层。示例用单进程原子替换与期望版本检查验证这一思想，不冒充分布式事务实现。

### 融合与重排

BM25 分数和向量相似度不在同一标尺上，示例使用 Reciprocal Rank Fusion（RRF）融合名次，而不是直接相加原始分数。重排是在较小候选集上使用更昂贵的相关性判断；是否启用以及候选规模必须由离线评测和线上延迟预算决定。

## 示例设计

`examples/10-retrieval-rag-agentic-search/hybrid_retriever.py` 使用 Python 标准库实现：

- 带 Tenant、Principal、Metadata、文档版本和稳定 Chunk 引用的内存索引；
- 可运行的滑窗切分、BM25、向量余弦相似度和 RRF；
- 在两类评分之前执行权限与属性过滤；
- 拒绝陈旧更新和同版本冲突，支持带期望版本的删除；
- 保留引用的证据格式化；
- 带最大步数和重复查询检测的 Agentic Search 外层循环。

Embedding 通过函数注入。测试使用手写概念向量 Test Double，只证明稠密检索的接口和排序行为，不声称复现真实模型语义能力。
